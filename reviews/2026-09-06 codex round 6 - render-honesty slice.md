## Findings

1. **Severity: Medium — the first partial fragment reads the next fragment's integral.** Evidence: `squint.html:1305`, `squint.html:1308`, `squint.html:1315`, `squint.html:888`. The expression `xs0 = Math.max(0, Math.ceil(ox))` excludes `floor(ox)`. For an interior pixel index `i`, the composite addresses `(i + 0.5 - xs0) / dispW`, correctly selecting texel `i-xs0`. But with `ox=0.25`, pixel 0 is inside the wall at its centre and addresses texel -1, which clamps to texel 0: the integral for screen pixel 1. Real Chrome reproduction: 2000×20 LEDs, 1000×10 viewport, cell 0.5, panX 0.25, only LED column 0 white, grid/blur off, neutral photometry and no quantisation. The first output pixel was **0**; its physical footprint contains 0.5 display pixels of white, so it should be approximately **188**. This loses the impulse entirely. Include every intersecting fragment, integrate its actual footprint, and treat the outside-wall portion consistently. This is separate from the explicitly deferred cabinet/array boundary approximation.

2. **Severity: Medium — the original minification alias returns above 64 texels per fragment without disclosure.** Evidence: `squint.html:1303`–`1304`, `squint.html:1329`, `squint.html:888`. The expression `if(cell<1 && per<=64)` otherwise leaves the composite sampling `led` with NEAREST. Real Chrome: 8000×800 alternating vertical LEDs, 100×10 viewport, panX 0.25, grid/blur off, bits 16 gives `cell=0.0125`, `decim=1`, `dispReduce=false`, `failed=false`, and an all-white sampled row (**255**, expected approximately **188**). The plan records this fallback, but README.md's “One LED never stands in for several” and README.txt's corresponding unconditional claim are false. It can also occur in a larger viewport after zooming out; “canvas under ~128 px” is not the general condition. Integrate the larger footprint with a valid staged/tiled method, or explicitly refuse/flag this approximation in the frame and export and document the actual threshold.

3. **Severity: Medium — decimation enlarges the physical LED mask.** Evidence: `squint.html:760`, `squint.html:1303`, `squint.html:1313`–`1314`, `squint.html:1329`. `lit = sqrt(fill)` is integrated once per source texel of the decimated field, although one such texel spans `decim` physical LEDs. The resulting mask has period `decim` LEDs and centred lit width `decim*sqrt(fill)`, rather than period one LED. `uGrid=2` then suppresses the original physical coverage calculation. This is an additional geometry/brightness error, not the acknowledged quantise-before/after-average limitation. Real Chrome, constant code-100 source, 128×20 LEDs, 100×20 viewport, fill 0.5, grid on, bits 16: native first 12 middle-row values were `[93,100,100,86,99,100,95,91,100,100,89,97]`; forced cap 64 (`decim=2`) gave `[108,92,116,100,92,122,92,95,120,92,104,112]`. Constant radiance with no quantisation should retain the same physical mask. Integrate the repeated native emitter mask in coarse-texel coordinates, including crop phase, or retain the physical coverage calculation for an explicitly approximate fallback. Add a pixel comparison, not merely the fallback-string check.

4. **Severity: High — a failed or approximated B panel can leave the application as an apparently valid comparison PNG.** Evidence: `squint.html:1496`, `squint.html:1503`, `squint.html:1608`, `squint.html:2011`, `squint.html:2018`, `squint.html:2082`. The refusal is only `if(geoA && geoA.failed)`; the fallback caption is only `decimNote(geoA.decim)`. Yet A/B renders B independently and unconditionally copies its canvas. A smaller B pitch or larger B content target can fail `grab` while A succeeds; likewise B alone can decimate. Wipe discards the ideal render's returned failure flag altogether. Check all panels included in the exported artifact, propagate ideal-view failure, and identify approximation per panel. `exportTemplate` does check A's failure, as requested, but that does not close comparison-export refusal.

5. **Severity: Medium — allocation refusal loses ownership of already allocated textures.** Evidence: `squint.html:1045`, `squint.html:1063`–`1067`, `squint.html:1079`–`1087`, `squint.html:1268`–`1270`, `squint.html:1374`–`1382`. In `boxTo`, `grab(dw,dh,...)` can throw before `give(owned)`; `reduceTo` similarly loses `mid` when its second grab throws. The render catch only clears/toasts, with no release of content, processor stage, LED field or scene still checked out. Concrete executed call: `boxTo(t,130,1,2,MAXTEX+1,false)` throws `texture 2x16385 exceeds MAX_TEXTURE_SIZE 16384` after successful reduction allocations; the final owned 2×1 texture is neither returned nor explicitly deleted. This can repeat during redraws, aggravating the allocation failure and invalidating the pool budget as an accounting bound. Use exception-safe ownership cleanup at helper and frame scope, preserving successful return ownership. Add a failure-injection assertion that every acquired texture is returned or deleted.

6. **Severity: Medium — the regression gate does not meet several Required regression bullets.** Evidence: `squint.html:2347`–`2354`, `squint.html:2356`–`2367`, `squint.html:2397`–`2410`. Alpha tests cover opaque red against fully transparent green/white only; there is no transparent-black case, partial-alpha edge, gradient, reduction or independently precomposited equivalent. Quantisation uses one 5000-LED view and checks only a string when forcing fallback: no matched-region pan/zoom/viewport sweep or 4095/4096/4097 transition. General phase sweeps call `sweep(...,false)` for blur; blur-on coverage is restricted to period-2 vertical stripes, which become constant and cannot reveal blur errors. Period-2 H/checkerboard cases are also absent. Interior samples beginning at pixel 20 miss finding 1. Add the audit-required regressions and magnified opaque before/after pixel comparisons before claiming all four findings closed. The expectations that do exist are independently computed; this is a coverage finding, not an accusation of circular tests.

7. **Severity: Medium — appending the fallback warning does not ensure it appears in the PNG.** Evidence: `squint.html:2015`, `squint.html:2072`–`2082`. The caption is one unwrapped `fillText` at x=120 in a canvas whose width is just the view width (or summed A/B widths). The warning is appended after the entire settings sentence. At narrow export widths it is clipped entirely; no measurement, wrapping, fitting or reserved warning region exists. Thus code that calls `decimNote` is insufficient evidence for “export caption both say so whenever it happens.” Reserve visible space for the warning and test its inclusion in the decoded output at narrow and ordinary sizes. This is a visibility issue even when A itself is the fallback panel.

## Confirmed correct

- **65 taps are sufficient:** `squint.html:773`–`789`. The positive-overlap texel count is `ceil(frac(s0)+r) <= 65` for `0 < r <= 64`; fractional or negative origins do not require a 66th tap. The lit weights use `acc/r` per axis (`squint.html:791`), correctly preserving dark unlit area rather than renormalising it away. At source edges, CLAMP_TO_EDGE extends the edge value; this is not a zero-outside-wall integral. On the trailing intersecting fragment that extension is bounded spatially to that fragment. Leading-fragment selection is the separate defect above.
- **Interior mapping has no half-texel error:** substituting `wall=(i+0.5-ox)/cell`, `sOx=(xs0-ox)/cell`, and `sDecim=1/cell` yields `uv=(i+0.5-xs0)/dispW`. For grid-off fallback, dividing the origin and footprint by `decim` is dimensionally correct. The fallback mask is the separate issue above.
- **Aligned stage selection is correct:** `squint.html:497`–`498`, `squint.html:1055`–`1057`. Every intermediate is a multiple of the final target, preserving final boundaries; each stage ratio is at most 64. Ran `node tools/test-reduce-stages-node.js squint.html`: **9 passed, 0 failed**, 1020 boundary impulses, 500 random reductions, maximum CPU chain/oracle error `1.11e-15`; the old-rule red proofs pass.
- **Uniform reset and bilinear conventions:** `squint.html:1051`–`1052` resets `uS0`, `uRatio`, `uLit` for every ordinary reduction pass. `squint.html:807`–`813` uses texel-centre coordinates `vUV*uSrc-0.5`, clamps each tap, and premultiplies in decoded linear light before mixing. Actual source/owned dimensions supplied to copy are integer texture dimensions; no non-integer `uSrc` caller was found. Opaque interpolation is algebraically equivalent to hardware LINEAR apart from implementation weight precision. I did not establish the blanket <=1 final sRGB code guarantee across nonlinear quantisation with a before/after image suite.
- **Native crop edge limits:** `squint.html:1246`–`1250` bounds each rounded crop-buffer axis by `min(NATIVE_CAP,MAXTEX)`, including elongated crops. `sqrt` is not an axis-allocation vulnerability because of the independent maximum-axis term. It is not an exact 24-million-texel bound after ceiling: `cw=12001,ch=7999,decim=2` gives `6001*4000=24,004,000`. `grab` has no 24-million-area limit, so this small overshoot does not itself trigger refusal. Content/processor/scene buffers are separately sized and can still refuse; a bounded LED crop does not guarantee that every frame allocation fits.
- **Refusal and self-test:** oversized `grab` throws before allocation; incomplete framebuffer creation deletes its own failed resources (`squint.html:972`, `squint.html:982`–`984`). The render catch sets `failed`, clears the default framebuffer black and toasts; both export functions inspect A's flag. `selftest()` was directly compared with `e3cc230` and is byte-identical, including its try/catch.

Per-pixel 3 / mean 2 tolerances match the recorded decision. `{...S}` semantics cover the fields the probe replaces, source invalidation forces the restored source to upload, and the forced cap restores in `finally`. Ordinary completion returns fixture targets to the bounded pool; after probe plus self-test this run retained **260,966,272 bytes**. The two-native-field comment is not a proof that the worst realistic case cannot thrash. No sustained pan/allocation benchmark was run.
